## ADDED Requirements

### Requirement: JSON Schema covers all 17 top-level configuration sections
The extension SHALL provide a JSON Schema file at `schemas/reltio-metadata.schema.json` that validates the complete Reltio Business Model structure. The top-level object SHALL accept the following sections: `description`, `attributeTypes`, `entityTypes`, `changeRequestTypes`, `roles`, `groupTypes`, `matchActions`, `relationTypes`, `interactionTypes`, `graphTypes`, `categoryTypes`, `survivorshipStrategies`, `sources`, `ratings`, `activity`, `groupingTypes`, `hierarchyTypes`; and metadata properties: `schemaVersion`, `createdTime`, `updatedTime`, `createdBy`, `updatedBy`, `referenceConfigurationURI`, `abstract`, `flatOvCalculation`, `label`, `uri`, `rdmTenantId`, `pinIgnoredPriority`.

#### Scenario: Valid top-level properties accepted
- **WHEN** a `.reltio.json` file contains only known top-level properties (any combination of the 17 sections and 12 metadata properties, plus `$schema`)
- **THEN** no validation errors SHALL be reported

#### Scenario: Unknown top-level properties rejected
- **WHEN** a `.reltio.json` file contains an unknown property at the top level
- **THEN** the editor SHALL display a validation error indicating the property is not allowed

### Requirement: Schema validates entity type definitions
The schema SHALL validate entity type objects within the `entityTypes` array, requiring `uri` and accepting all ~30 child elements (attributes, matchGroups, survivorshipGroups, associationGroups, surrogateCrosswalks, cleanseConfig, cleanse, dataPipelineConfig, activenessAttributes, geoLocationAttributes, dataLabelPattern, secondaryLabelPattern, dataTooltipPattern, entityTypeRoleURIs, businessCardAttributeURIs, imageAttributeURIs, matchAssets, defaultFacetedAttributes, defaultSearchAttributes, dependentAttributes, lifecycleActions, analyticsAttributes, extendsTypeURI, hidden, unmerge, ruleBasedAttributes, indexingConfig, groupLabels, precedingCleanseProcedureUris, succeedingCleanseProcedureUris) and ~22 attributes (uri, label, typeIcon, typeImage, typeGraphIcon, typeColor, entitySmartLogic, abstract, singleDefaultCrosswalk, matchBeforeCreate, configurationLessMatching, cleanseInputObjectBeforeOverwrite, searchable, validateRequiredAttributes, overrideIgnorePin, uniqueGeneratedValuePerEntityPerRequest, ignoreWarnings, skipValidationForAbstractType, ignoreNonOVChangesWhenUpdateThroughReferencedEntity, useOnlyOvValuesInReferencedEntities, forceOvForUiUpdates, defaultSurvivorshipStrategy).

#### Scenario: Valid entity type accepted
- **WHEN** an entity type has `uri` and any valid combination of child elements and attributes
- **THEN** no validation errors SHALL be reported for that entity type

#### Scenario: Entity type missing required uri
- **WHEN** an entity type object is missing the `uri` property
- **THEN** the editor SHALL display a validation error on that entity type object

#### Scenario: Entity type with unknown property rejected
- **WHEN** an entity type contains a property not defined in the schema
- **THEN** the editor SHALL display a validation error indicating the property is not allowed

### Requirement: Schema validates the full attribute model
The schema SHALL validate attribute objects with all properties defined in the XSD `attributesType`: ~30 attributes (uri, type, name, label, hidden, important, faceted, searchable, system, required, prioritizeOv, matchOvOnly, matchFieldURIsIgnoreCase, keyAttributeURIsIgnoreCase, lookupCode2, resolveLookupCode, survivorshipStrategy, dataLabelPattern, relationshipLabelPattern, relationshipTypeURI, referencedEntityTypeURI, referenceAttributeDirection, autoGenerated, generator, autoGenerationPattern, generateIfEmpty, generateIfNotEmpty, generatedValueUniqueForCrosswalk, defaultValue, skipInDataAccess, customReltioId, vectorized) and ~30 child elements (values, dependentLookupAttributes, attributes (recursive), referencedAttributeURIs, immutableForSources, immutableExceptForSources, immutable, doNotOverrideForSourceURIs, matchFieldURIs, matchFieldURIsExactOrNull, matchFieldURIsExactOrAllNull, keyAttributeURIs, keyAttributeURIsExactOrNull, keyAttributeURIsExactOrAllNull, singleValue, singleValueByCrosswalk, singleValueByCrosswalkSources, description, attributeOrdering, masking, autoGenerationNestedPattern, cardinality, indexingConfig, enableNestedPartialOverride, lookupCode).

#### Scenario: Simple attribute accepted
- **WHEN** an attribute has `uri` and `type` set to a string value
- **THEN** no validation error SHALL be reported

#### Scenario: Nested attribute with recursive sub-attributes
- **WHEN** an attribute has an `attributes` array containing further attribute objects
- **THEN** the schema SHALL validate the nested attributes recursively with the same rules

#### Scenario: Attribute with unknown property rejected
- **WHEN** an attribute contains a property not defined in the schema
- **THEN** the editor SHALL display a validation error

### Requirement: Schema validates relation types with endpoint objects
The schema SHALL validate relation type objects with `startObject` and `endObject` as structured objects (not simple strings), each containing `objectTypeURI`, `uri`, and an optional `directionalContext` array.

#### Scenario: Relation type with structured endpoints
- **WHEN** a relation type has `startObject: { objectTypeURI: "..." }` and `endObject: { objectTypeURI: "..." }`
- **THEN** no validation error SHALL be reported

#### Scenario: Directional context on endpoint
- **WHEN** an endpoint object has a `directionalContext` array with objects containing `labelPattern` and `uri`
- **THEN** no validation error SHALL be reported

### Requirement: Schema validates match group rule composition
The schema SHALL validate match groups with a recursive rule system supporting `exact`, `fuzzy`, `exactOrNull`, `exactOrAllNull`, `ignoreInToken`, `cleanse`, `or`, `and`, `not` composition, `matchTokenClasses`, `comparatorClasses`, `nullValues`, `equals`, `notEquals`, `notExact`, `in`, `multi`, `weights`, and `actionThresholds`.

#### Scenario: Simple match rule with exact operands
- **WHEN** a match group has a `rule` with `exact` string values
- **THEN** no validation error SHALL be reported

#### Scenario: Composite match rule with or/and nesting
- **WHEN** a match group rule contains `or` and `and` sub-rules that themselves contain `exact` and `fuzzy` operands
- **THEN** the schema SHALL validate the nested structure recursively

#### Scenario: Negative match rule
- **WHEN** a match group has a `negativeRule` with `notExactSame` and `notFuzzySame` operands
- **THEN** no validation error SHALL be reported

### Requirement: Schema validates survivorship groups with recursive mappings
The schema SHALL validate survivorship groups with a `mapping` that includes `survivorshipStrategy`, `attribute`, filter conditions, and recursive `fallbackStrategies`.

#### Scenario: Survivorship mapping with fallback chain
- **WHEN** a survivorship group mapping has `fallbackStrategies` containing further mapping objects
- **THEN** the schema SHALL validate the nested mappings recursively

#### Scenario: Survivorship filter with comparison operators
- **WHEN** a survivorship mapping has a `filter` with `equals`, `gt`, `lt`, `missing`, `exists`, `in`, `notIn`, `or`, and `and` conditions
- **THEN** no validation error SHALL be reported

### Requirement: Schema validates cleanse configuration
The schema SHALL validate cleanse configurations including `mappings` (with input/output mapping definitions), `infos` (with sequence/chain structures), `addressAutoCompleteConfig`, and `attributeVerificationConfig`.

#### Scenario: Cleanse config with chain
- **WHEN** a cleanse config has `infos` with a `sequence` containing `chain` entries with `cleanseFunction`, `mapping`, and `params`
- **THEN** no validation error SHALL be reported

### Requirement: Schema enforces enum constraints
The schema SHALL enforce enumeration constraints on all fields that have restricted value sets in the XSD: `MatchGroupScope` (none, internal, external, all, ml_match + uppercase), `MatchMethod` (match_iq, rule_based), `EntityEndDateStrategy` (END_DATE_RELATION, END_DATE_RELATION_CROSSWALKS), `FallbackUsingCriteria` (ZERO_OR_MORE_THAN_ONE, MORE_THAN_ONE, ZERO), `GenerationLogic` (ovOnly, useFirstNonOvWhenOvMissing, etc.), `GroupingFunctionType` (fixedValue, copy, survivedValue, aggregate, count, countDistinct, groupingRule, srcCopy, topK, mostRecent, firstNonNull), `RuleBasedAttributeType` (Conditional), `PromptTemplate` (SINGLEVALUE, MULTIVALUE), `MultiAttributeCombinationsStrategy` (DROP_ALL, FIRST_N, NOOP).

#### Scenario: Valid enum value accepted
- **WHEN** a match group has `scope` set to `"internal"`
- **THEN** no validation error SHALL be reported

#### Scenario: Invalid enum value rejected
- **WHEN** a match group has `scope` set to `"invalid_scope"`
- **THEN** the editor SHALL display a validation error indicating the value is not in the allowed set

### Requirement: Schema activates for *.reltio.json files
The extension manifest SHALL register JSON validation via `contributes.jsonValidation` for the `*.reltio.json` file pattern. Files MAY also use a `$schema` property pointing to the schema for validation without the extension loaded.

#### Scenario: Automatic schema association
- **WHEN** the extension is loaded and a file matching `*.reltio.json` is opened
- **THEN** the JSON Schema validation, autocomplete, and hover docs SHALL be active

#### Scenario: Inline $schema reference
- **WHEN** a JSON file contains `"$schema"` pointing to the schema file
- **THEN** validation SHALL work regardless of the file name or extension activation state

### Requirement: Schema provides autocomplete and hover documentation
The JSON Schema SHALL include `description` fields on all properties so that VS Code's built-in JSON language server provides autocomplete suggestions and hover documentation.

#### Scenario: Autocomplete for entity type properties
- **WHEN** the user triggers autocomplete inside an entity type object
- **THEN** the editor SHALL suggest all valid entity type properties (attributes, matchGroups, uri, label, etc.)

#### Scenario: Hover documentation on property
- **WHEN** the user hovers over a property name
- **THEN** the editor SHALL display the property's description from the schema
